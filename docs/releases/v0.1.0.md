remimem 0.1.0: codebase memory for coding agents.

remimem is a local-first MCP server and CLI. It indexes a codebase by structure and gives a coding agent the smallest set of code that answers its question, within a token budget, together with project memory that persists across sessions.

## What is in this release

- Structural indexing for TypeScript, JavaScript, Python, and Go, and text indexing for everything else.
- Hybrid search: an identifier-aware keyword index, a local embedding model, and exact symbol lookup, fused by rank.
- A call graph that adds the callers, callees, base classes, and referenced types of the top results as signatures.
- Token-budgeted answers with `path:start-end` headers, a reason on every result, and a footer that says what was dropped.
- Project memory: decisions, conventions, and gotchas linked to code, shared through a committed JSON file, and flagged when the code changes.
- Nine MCP tools and a CLI. Works with Claude Code, Cursor, VS Code Copilot, and any MCP client.
- Everything runs locally. No telemetry.

## Benchmark

On 36 held-out tasks taken from real commits in hono, httpx, and echo, `get_context` at 4,000 tokens serves 3,827 tokens per call on average, against 27,529 read by a simulated grep-and-read agent (86% fewer, counting the tasks that agent failed at its 40,000-token cap). On average 0.93 of a task's ground-truth files are among the ten best-ranked files, against 0.79 for the baseline. The full table, the method, and what the numbers do not show are in the README.

## Getting started

```sh
npx -y remimem init
claude mcp add remimem -- npx -y remimem serve
```

Requires Node.js 22.13 or newer.

## Known limitations

- The benchmark tasks are commit messages, which are easier than bug reports, and the test split is small.
- The call graph has no type inference; about one in four links made by name alone was wrong in a hand-check.
- The OpenAI and Voyage embedding providers are tested only against stubs.
- The local embedding runtime is large: about 430 MB in `node_modules`.

The README has the full list.
